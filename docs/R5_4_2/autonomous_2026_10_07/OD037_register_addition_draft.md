

## OD-037 — complete finite purpose variants in installed policy dispatch

**OWNER-DELEGATED DESIGN DECISION.** Concrete initial policy construction and complete Data 30/43/48/68/70/184 plus OD003/021/035 review expose an expressiveness defect: one (purpose, governing spec) row can bind only one METHOD method_type or ASSESSOR assessment_kind_version, so the same full-path policy cannot select all mandatory distinct assessment contracts. Selected: required closed variant discriminator in each FULL_PATH_CONTEXT_PARAMETERS_V2 row. Fourteen ordinary purposes use {kind:DEFAULT}; METHOD uses {kind:METHOD, method_type:existing finite MethodType}; ASSESSOR uses {kind:ASSESSOR, assessment_kind_version:one of the four exact existing assessment keys}. Complete initial spec coverage is exactly 32 sorted unique purpose/variant tuples: 14 DEFAULT, 14 methods, four assessments. Each governing spec must have complete coverage, with exact algorithm and variant parameter equality; absent/duplicate/unknown/mismatched selection rejects. Derive method variant from the exact prior subject ExperimentSpec, and assessment variant from the actual registered assessment contract under the authorized invocation; caller selectors cannot confer authority. All input/witness/output/resource domains and independent authorization/applicability/no-omission predicates remain mandatory. No new purpose, generic expression, merged result domain or new mutable authority is introduced. OD021's complete spec/purpose enumeration becomes complete spec/purpose/variant enumeration. The unqualified V2 context successor is amended before freeze; historical V1 bytes and all already qualified predecessors remain unchanged. Alternatives: silently choose one assessment family, collapse result enums, replace policy mid-investigation to reinterpret facts, or allow arbitrary caller dispatch. Rejected. Required controls: all 32 representable contexts; missing/duplicate/unknown variants; wrong order; cross-variant predicate pin; wrong governing spec; exact actual predicate parameters and issuer context before use. Draft configuration checks do not prove trusted installation, scientific judgment or canonical acceptance. Full source/body/profile/predicate parity and fresh qualification remain required.
