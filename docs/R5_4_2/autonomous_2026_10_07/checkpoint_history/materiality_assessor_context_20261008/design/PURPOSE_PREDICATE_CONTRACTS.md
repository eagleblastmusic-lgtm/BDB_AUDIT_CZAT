# Purpose-specific predicate contract decisions

OWNER-DELEGATED DESIGN DECISION OD-003. Design input for the successor, not yet a qualified installed profile. Each family has one fixed algorithm, a closed input domain, a closed policy-parameter domain, finite output states and the rules below. No expression/eval field, arbitrary checker name, embedded secret, caller `trusted` flag or unspecified success fallback is permitted. Profile changes require a new exact installed revision; changed canonical bodies/reference contracts require kind version successors.

## Shared execution and identity obligations

The predicate evaluator receives a verified accepted HistoryCut and exact subject reference, dereferences the complete specified input closure from history, reads retained raw dependencies and resolves every profile/schema through that campaign's qualified installation context. Caller supplied resolved bodies, scalar statuses, digests and summaries are compared with independent derivation and never substitute for it. Every authority ref must be visible at its declared cut. Context/profile roots must predate the operation; allowed content refs obey their explicit object ordering contract. Terminal transitions and delivery authorization are serialized against the same accepted head. A cut can be old only for a explicitly pinned historical assessment, with independent applicability revalidation before current consumption.

A profile instance is closed `{profile_id, algorithm_id, parameters}`. `profile_id` and `algorithm_id` are constants per family below. Parameters have exactly the listed fields, no others. Their typed refs are installation-authorized/planned before use, not newly asserted authority. Integers are BDB safe integers; counts and resource limits are nonnegative and <=9007199254740991; text/code lists are finite sorted unique sets, max65536 entries. Resources are exactly CPU_TIME_US, WALL_TIME_US, MEMORY_BYTES, OUTPUT_BYTES, FILE_COUNT. Missing parameters reject profile installation; evaluation must not use defaults. Empty required sets are legal only where the pinned subject spec independently declares none. JSON float, duplicate key, unknown enum, malformed ref or unsupported parameter rejects before canonical acceptance. Resource exhaustion produces unavailable/blocked output, never partial success.

For each successful computed output, the canonical object's proposed output must equal it. Negative evaluation may be retained as a truthful eligible assessment/decision, but a proposed success object fails. A rejected canonical operation makes no change to head, commits, events, immutable objects, receipts, indexes, selectors or accepted raw refs. Any separately staged raw is nonauthoritative until the legal operation accepts its reference. A runtime capability is an unexported security primitive, never canonical evidence.

## STAGE — STAGE_COMPLETION_V1

Inputs: exact StageRun, its StageSpec, input cut; independently selected required LaneCompletion objects, complete required output slot bindings, source-bound inventory/accounting, applicable obligations/qualifications and material unresolved facts at that cut. Output: SATISFIED, VIOLATED, UNKNOWN, BLOCKED. Parameters: `{spec_selection:"EXACT_STAGE_RUN_REF", completion_output_kind_versions:SchemaKey[], required_qualification_status:"QUALIFIED"}`. Keys are exact versioned schema keys from the qualified installation. Each StageRun selects its exact accepted StageSpec; the predicate profile does not contain a backlink to its future StageSpec consumer.

SATISFIED iff (1) StageRun is in COMPLETION_CANDIDATE; (2) each required StageSpec lane slot has exactly one applicable accepted LaneCompletion with matching run/spec/source/slot; (3) independently enumerated outputs equal the complete required outputs, including E5A candidate and E5B both challengers where the actual StageSpec requires them; (4) all mandatory applicable investigation obligations have current eligible QUALIFIED assessments satisfying their exact acceptance/control/applicability predicates; (5) accounting is terminal, knowledge/isolation/disclosure checks are satisfied; (6) no material unresolved contradiction, required unknown scope, stale/invalidation or required unavailable witness remains. Confirming a defect may satisfy investigation and does not mean release readiness. Optional lanes never fill missing required slots. STOP/conclusion/final/release/public statement are not stage completion prerequisites. VIOLATED for established binding/FSM/predicate mismatch; BLOCKED for a recorded execution/resource blocker; UNKNOWN for missing/unverifiable required fact. No waiver/risk acceptance turns a required investigation into performed work.

## LANE — LANE_COMPLETION_V1

Inputs: exact LaneRun/LaneSpec, Attempt lineage, assignment/binding/STARTED/admission/result chain for each selected result slot, final KnowledgeState, complete outputs, IsolationQualification and ContaminationAssessments. Output: SATISFIED, VIOLATED, UNKNOWN, BLOCKED. Parameters: `{spec_selection:"EXACT_LANE_RUN_REF", allowed_result_kind_versions:SchemaKey[], required_isolation_results:(ENFORCED|DECLARED)[]}`. No UNKNOWN isolation eligibility; the selected LaneSpec can require stricter enforcement.

SATISFIED iff eligible lane FSM, every required exact slot has one accepted result with prior evidence and independently retained normalization, required outputs equal slot contracts, all attempts/source/profile/cuts agree, final knowledge/exposure policy is satisfied, isolation meets the exact LaneSpec and every required contamination result is CLEAN or a separately justified policy-permitted NOT_APPLICABLE. Result existence is one conjunct only. Forked attempt/slot selectors, late result into completed lane, wrong binding and cross-lane reused evidence are VIOLATED. Missing witness is UNKNOWN; actual blocker BLOCKED. Exact retry returns original fact, never reselects a latest attempt.

A declared capability is not an enforcement witness.

Output: ALLOW, DENY, UNKNOWN, BLOCKED. Parameters: `{delivery_selection:"EXACT_ASSIGNMENT_CONTEXT", require_binding:true, require_started:true, raw_source:"DURABLE_RAW_VAULT", retry_mode:"EXACT_AUTHORIZED_BYTES"}`.

No fallback to workspace.

## COLLECTOR — COLLECTOR_ACCOUNTING_V1

## METHOD — METHOD_QUALIFICATION_V2

Inputs: prior ExperimentSpec/ExecutionDescriptor, retained observations, execution/control/cleanup facts, dependency graph and current claim-relative applicability/independence qualification. Output: QUALIFIED, REFUTED, INCONCLUSIVE, BLOCKED. Parameters: `{method_type:STATIC_ANALYSIS|DYNAMIC|FAULT_INJECTION|FUZZ|PROPERTY|DIFFERENTIAL|METAMORPHIC|STATEFUL|CONCURRENCY|ENDURANCE|IMPLEMENTATION_MUTATION|ORACLE_CHALLENGE|MODEL_CONFORMANCE|REPLAY, control_selection:"EXACT_PRIOR_SUBJECT_EXPERIMENT_CONTROLS", required_observation_kinds:Code[], required_independence_dimensions:Code[]}`. Observation codes and independence dimensions are exact Data §46/§48 domains. Policy cannot add a method by a string. Controls are derived from the subject's exact prior ExperimentSpec positive_controls/negative_controls and actual corresponding executions, not pinned as future experiment facts inside the installation profile. Complete method-specific controls remain mandatory; a subject declaring fewer controls than the method requires is INCONCLUSIVE/BLOCKED, never QUALIFIED. This V2 avoids the Policy→context→method-profile→future-experiment→Policy chronology cycle. The V1 analysis label is navigation only; the final runtime pin is exact V2.

QUALIFIED means the selected method's investigation requirements are actually established, independently of whether a defect was found. Preregistration requires accepted intent before actual execution; exploratory/legacy execution cannot obtain it retroactively. All expected observations and controls must exist and match scope/input/descriptor. Fault requires independent activation; ENDURANCE requires observed workload/duration and monitoring completeness; MODEL_CONFORMANCE requires prior applicable fidelity and actual conformance witnesses; replay alone provides no independence. IMPLEMENTATION_MUTATION and ORACLE_CHALLENGE use their distinct §68 enums; oracle qualification requires all four exact clean/defective × strong/weakened cases, qualified activation and actual outcome derivation. Clean PASS alone never establishes weakening detection. Established contrary expected predicate yields REFUTED; ambiguous/missing evidence INCONCLUSIVE; actual blocker BLOCKED. A human scientific assessment remains an authorized ASSESSMENT of exact support, not an arbitrary executable expression or declaration of product truth.

## CONFIRMATION — DISCOVERY_CONFIRMATION_V1

Inputs: exact DiscoveryRecord, complete accepted supporting/refuting EvidenceQualifications with current applicability and their exact experiments/observations; cut. Output: CONFIRMED, NOT_CONFIRMED, INCONCLUSIVE, BLOCKED. Parameters: `{permitted_modes:(PREREGISTERED|EXPLORATORY|LEGACY_IMPORTED)[], require_current_applicability:true, require_exact_discovery_scope:true}`.

Every evidence entry must address the exact discovery mechanism/scope under an authorized confirmation assessment. CONFIRMED requires decisive SUPPORTS and no unresolved decisive REFUTES/contradiction; NOT_CONFIRMED requires decisive REFUTES with no unresolved decisive support; mixed, missing or inconclusive support yields INCONCLUSIVE. Blocked required execution yields BLOCKED. Preregistered mode requires prior intent; imports preserve their mode. Confirmation does not establish blindness, novelty or adjudicated finding truth. A caller matching strings does not establish that evidence is about the discovery.

## MATCHING — EXACT_SCOPED_MATCH_V1

Inputs: DiscoveryRecord or FindingClaimRevision, every eligible prior member in the exact pinned CorpusManifest, their current source/scope/invariant/mechanism facts and any already accepted authorized finding-to-defect matching assessment. Output: MATCH, NO_MATCH, PARTIAL, INCONCLUSIVE. Parameters: `{candidate_policy:"ALL_ELIGIBLE_MEMBERS", exact_match_rule:"EXACT_SUBJECT_SCOPE_INVARIANT_AND_MECHANISM", unknown_overlap:"INCONCLUSIVE", require_complete_corpus:true}`.

Exact subject source identity, complete canonical scope identity set, exact violated invariant revision set and exact canonical mechanism/claim statement bytes establish an exact match. An eligible previously accepted matching assessment may establish a scientifically assessed match only for its exact pair/cut and current qualified support; name similarity or edit distance cannot. NO_MATCH requires a complete search in which every candidate is proved disjoint by exact scope/invariant applicability; differing prose does not prove disjointness. Established match plus unresolved overlapping candidates gives PARTIAL; possible unresolved semantic overlap or incomplete corpus gives INCONCLUSIVE. No search truncation, outcome filter or favorable subset. This conservative algorithm permits genuine unknowns instead of inventing semantic equivalence.

## NOVELTY — CORPUS_RELATIVE_NOVELTY_V1

Inputs: prior exact matching assessment for the same discovery/corpus and cut-applicable history. Output: NOVEL, PREVIOUSLY_KNOWN, PARTIALLY_NOVEL, INCONCLUSIVE. Parameters: `{basis:"EXACT_PINNED_CORPUS", missing_basis:"INCONCLUSIVE"}`.

Complete NO_MATCH maps to NOVEL; complete MATCH to PREVIOUSLY_KNOWN; established matched and independently established unmatched subscopes in a PARTIAL assessment map to PARTIALLY_NOVEL; all incomplete/ambiguous cases map to INCONCLUSIVE. No statement about universal novelty or blind provenance follows. A different matching subject/corpus or stale material basis rejects, not INCONCLUSIVE acceptance under the wrong identity.

## RELATIONSHIP — PRIOR_FALSE_NEGATIVE_V1

Inputs: exact confirmed discovery, prior StageCompletion/claim, mandatory applicable prior coverage obligation and its eligible investigation scope, actual missed result/adjudication and current discovery qualification. Output: PREVIOUS_FALSE_NEGATIVE, MULTI_STAGE_FALSE_NEGATIVE, NOT_ESTABLISHED, INCONCLUSIVE. Parameters: `{minimum_prior_stages:positive safe integer, scope_rule:"EXACT_REQUIRED_APPLICABLE_SCOPE", unknown_rule:"INCONCLUSIVE"}`.

A prior stage counts only if it was required to investigate the exact issue's applicable scope and accepted completed investigation without identifying it; actual current decisive confirmation and source applicability are required. If the count meets minimum_prior_stages, one established stage gives PREVIOUS_FALSE_NEGATIVE and two or more distinct established stage identities give MULTI_STAGE_FALSE_NEGATIVE; a positive established count below the required minimum gives INCONCLUSIVE. Proved scope absence gives NOT_ESTABLISHED, not an accusation of missed coverage. Missing/unverifiable prior obligation or discovery basis gives INCONCLUSIVE. Counts are independently derived distinct stage refs; threshold cannot turn incomplete evidence into a confirmed relationship.

## ASSESSOR — CLAIM_RELATIVE_ASSESSMENT_V1

Inputs: exact claim or calibration opportunity, authorized assessor principal/profile at cut, qualified observations/evidence, accepted ground truth where applicable, complete subject scope and opposing evidence. Output domains remain the exact selected assessment contract: M/R/I SUPPORTED|REFUTED|INCONCLUSIVE|BLOCKED|NOT_APPLICABLE; severity CRITICAL|HIGH|MEDIUM|LOW|INFO with confidence HIGH|MEDIUM|LOW|UNKNOWN; calibration MATCH|NO_MATCH|PARTIAL|UNRESOLVED or TRUE_NEGATIVE|FALSE_POSITIVE|UNRESOLVED|BLOCKED. Parameters: `{assessment_kind_version:SchemaKey, authorized_principal_refs:ExternalProfileRef[], require_current_applicability:true, require_opposing_evidence_accounting:true}`. Principal authorization pins are external authority context, not references to future assessor facts.

The assessment-specific domain is selected by an exact finite installed schema key; it cannot be caller-inferred from a generic `result`. Adjudication axes remain separate and scope/claim/cut bound. The validator verifies authorized production, complete qualified basis and applicability; scientific judgment must be issued by that authorized assessor and may remain INCONCLUSIVE. Ground truth comes from a prior independently authorized corpus, never the tested auditor output, majority, match count or producer string. Severity is an assessed dimension, not copied caller-reported severity. NOT_APPLICABLE requires exact separate applicable policy/decision; unsupported target/profile rejects. An assessor's authorization never upgrades evidence strength or overrides an unresolved material contradiction.

Parameters: `{activation_check_refs:RawRef(CLEANUP_EXPECTED_OBSERVABLE_V1)[], required_cleanup_profile_ref:ExternalProfileRef, require_all_targets:true}`. Activation uses the same finite exact capture equality grammar, not arbitrary eval.

Missing required resource/capture→BLOCKED, malformed/failed harness capture→HARNESS_FAILURE. Missing observations do not mean NOT_ACTIVATED. Actual cleanup assessment remains separate. Raw plus caller status and matching digest cannot establish activation. Neither partial nor unactivated fault satisfies an activation-required obligation.

## EFFORT — OBSERVED_EFFORT_V2

Inputs: complete applicable accepted stage/execution/observation/discovery/root-cause/obligation/challenger histories at exact cut, planned per-stage required rounds/methods/resources and observed metric witnesses. Output: SATISFIED, INSUFFICIENT_DATA, BLOCKED; saturation separately LOW|MODERATE|STRONG|INSUFFICIENT_DATA, never completeness. Parameters: `{stage_selection:"EXACT_REQUIRED_STAGE_SET_AT_INPUT_CUT", stage_requirements:StageEffortRequirement[]}` where each closed requirement is `{stage_ordinal:integer(0..65536), minimum_rounds:positive safe integer, required_method_types:MethodType[], minimum_observed_work_units:safe integer, work_unit:EXECUTIONS|SOURCE_MEMBERS|OBSERVED_WORKLOAD_UNITS}`. Sort requirements by stage_ordinal, rejecting duplicate ordinals. Independently resolve the complete exact required StageSpec reference set at the input cut and apply each matching ordinal threshold to every required exact spec. The ordinal indexes configuration only; it cannot select history or authorize a spec. Every required spec must have one matching threshold; absent or ambiguous coverage yields INSUFFICIENT_DATA. Applicable rounds/work are derived separately for each exact spec/campaign/source, including legitimate same-ordinal successor runs, with no latest-by-ID lookup or cross-spec aggregation. Requirements for conditionally nonrequired stages cannot add those stages to authority. This V2 removes profile backlinks to future accepted StageSpecs; exact spec identities remain in independently resolved accepted context. The V1 analysis label is navigation only, never a runtime alias.

Round is a distinct accepted StageRun/Attempt exploration iteration explicitly identified by exact planned lineage, not upload retries. An execution work unit counts one exact eligible completed descriptor; source work counts distinct terminally accounted manifest members; workload counts independently captured integer units from required retained MEASUREMENT observations. Retries never double count. Required method coverage uses actual qualified Method facts, not names in a proposed output. Missing clock/workload/method/capture witnesses gives INSUFFICIENT_DATA, actual resource prevention BLOCKED. Only all applicable thresholds met gives SATISFIED. No history subset or assumed-zero metric. Rational rates use exact reduced numerator/positive denominator, unknown counts remain explicit; saturation never discharges scope/obligation/challenge guards.

## RECOVERY — EXACT_DURABLE_RECOVERY_V1

Inputs: exact stored accepted head/commit chain, immutable object/schema/profile closure, accepted raw refs, receipts/command indexes, external anchor only where trust requires it. Output: VERIFIED, CORRUPT, UNAVAILABLE. Parameters: `{receipt_policy:"RECONSTRUCT_FROM_ACCEPTED_COMMIT", raw_policy:"READBACK_ALL_ACCEPTED_REFS", head_policy:"EXACT_CHAIN", anchor_policy:LOCAL|EXTERNAL_REQUIRED}`.

VERIFIED requires complete consistent commit/object/raw closure and exact installed predecessor/current contract interpretation for every campaign; source and authoritative selectors are replayed from accepted events. Rebuildable indexes/receipts may be reconstructed only from that exact accepted chain and command identity, never workspace/cache. Each crashed operation yields complete durable accepted closure or no accepted operation. Missing required bytes/anchor→UNAVAILABLE; digest/length/chain/conflicting receipt/head mismatch→CORRUPT. Neither permits canonical resume/write/export until restored identical bytes are independently verified or an existing authorized recovery transition applies. No new binding/result/history is synthesized. Old campaigns remain readable with original exact contracts and cannot accept successor writes.

## Context dispatch and no-waiver rules

FULL_PATH_CONTEXT_PARAMETERS successor must bind each actual owner field to one of these exact purpose contracts and its finite kind/version inputs, output domain, current/prior cut rule and parameter schema. An unconstrained generic entry is forbidden. Shared common structures do not make purposes interchangeable. Guards for raw integrity, exact schema authority, prior-only membership, source/campaign binding, completeness of required facts, DAG ordering and identity equality are nonwaivable. Separate approved applicability/waiver/risk decisions affect only the already-defined domain predicate and never manufacture evidence or UNKNOWN→SATISFIED. Every field-to-purpose binding is generation-ready only after the own-body audit resolves it explicitly.
