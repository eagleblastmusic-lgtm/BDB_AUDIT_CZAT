# Specifications, checkpoints and snapshot model mapping

Complete Data sections 10, 11, 12, 13, 17 and 20 are mapped here. Registry build rows and build-time schemas preserve the required fields and exact finite profile selections. This is a static design review; actual installation, producer authorization and accepted-history predicates remain separate requirements.

Data 10 paragraphs 0–2: immutable StageSpec retains its key/revision, role/ordinal/purpose, predecessor requirements, required/optional lane slots, reveal model, allowed/forbidden corpus roles, obligation policy, required completion outputs, transition policy and STOP/E6 relationship. The selected coverage and transition profiles are exact pins. Paragraph 3 forbids reinterpreting an existing StageRun after a configuration change: a changed run selects a new exact specification revision. Stage completion must derive the complete required slot/output set from that accepted or independently installed exact specification, not caller lists. Paragraph 4 is a separator.

Data 11 paragraphs 0–2: immutable LaneSpec retains exact stage-spec revision context, strategy/purpose/scope selectors, exploration policy, view and knowledge restrictions, isolation assurance, outputs, capabilities, effort and completion predicate. The three external fields select EXPLORATION_POLICY_V2, OBSERVED_EFFORT_V2 and the exact lane-completion family. Paragraph 3 requires isolation class and forbidden exposure classes, never a blindness boolean. A Code or profile reference represents a class; independently qualified context must establish its finite meaning and capability satisfaction. Possession, different model names and copied status labels cannot establish blindness. Paragraph 4 is a separator.

Data 12 paragraphs 0–2: ExecutorSpec retains tool, optional model, runtime, filesystem/network/tool boundary pins, capabilities, isolation capabilities, freshness, evidence collection and limitations. Optional model identity does not waive runtime or boundary fields. Paragraph 3 explicitly separates model/tool differences from evidence independence and blindness. Applicable boundary qualification, exact code/runtime and authenticated execution must supply those properties. Paragraph 4 is a separator.

Data 13 paragraphs 0–2: DeliverySpec retains controlled channel, grant/view requirements, acknowledgment, retry/idempotency, exposure point, redaction and resolver capabilities. Exact DELIVERY_RETRY_V2, DELIVERY_IDEMPOTENCY_V2 and PUBLIC_REDACTION_V2 selections remain independently installed. Paragraph 3 places PotentialExposure at the accepted grant under policy, even without an executor ACK. Delivery retries cannot create a new knowledge grant, change assignment scope, acknowledge a different view or move the exposure boundary. Paragraph 4 is a separator.

Data 17 paragraphs 0–3: Checkpoint is an immutable precursor selecting exact prior stage, optional lane, attempt, source, knowledge state, input cut, outputs and governing policy. Optional lane is not an optional attempt or source. Sealed outputs permit content-or-prior targets only under the complete union DAG and purpose-specific checkpoint requirements. Paragraph 4 forbids mutable-state snapshot authority and an independent head; own digest and accepting provenance belong outside the checkpoint body. The accepted checkpoint precedes the relevant reveal/transition. Paragraph 5 is a separator.

Data 20 paragraphs 0–5: a snapshot remains a rebuildable materialization or explicitly historical legacy artifact. Native snapshot export is a separate wrapper retaining type, exact as-of head, retained projection code, prior projection inputs and snapshot RawRef. The projection-code raw contract is distinct from the snapshot payload contract. Original raw bytes cannot contain their own RawDigest. Deleting a projection cannot prevent reconstruction from canonical history and immutable content; snapshot export never creates a current head. The companion snapshot/2 model and SNAPSHOT_EXPORT_V2 payload contract must be reviewed with Data 105 before claiming complete snapshot parity. Paragraph 6 is a separator.

Remaining execution proof: exact installed/accepted specification and policy selection; complete lane/output/corpus scopes; accepted grants and reveal ordering; actual freshness/boundary/independence qualification; retry/delivery/view equality; full checkpoint output membership and source/cut applicability; retained snapshot/code bytes and reconstruction; durable rejection and concurrency; old-campaign preservation. Required runtime properties cannot be inferred from these static field/profile mappings.
