# Closed successor command and event bodies

OWNER-DELEGATED DESIGN DECISION OD-016. Data §§14–16 and §192 remain the semantic basis. Existing command_envelope/1 and commit_body/1 schemas permit unspecified object payloads; their successor bodies close these representations. This document is design input, not qualification or runtime authority.

The successor CommandEnvelope requires inline command_payload and forbids command_payload_ref. The payload is exactly `{proposed_object_refs:TypedRef[],events:EventBody[]}`. Proposed refs name the complete new fact/content closure supplied to acceptance, excluding the command itself, its accepting CommitBody and receipt. Referenced bodies are independently available, hash/schema checked, and union-DAG sorted. Payload references authorize neither their own producer nor a prior-only requirement. An empty proposed list is legal only for an independently legal transition command with prior basis. There is no arbitrary nested instruction bag or serialized capability. Governing policy/spec/actor/parent stay in the original envelope fields and cannot be contradicted by payload.

Four exact command_kind values: INITIALIZE_CAMPAIGN_FROM_LEGACY, ACCEPT_ARTIFACTS, TRANSITION, INGEST_EXTERNAL_LANE_RESULT. Initialization retains the original empty-parent/namespace/profile/proposed-campaign contract. Every other command requires the exact prior campaign/parent and forbids initialization-only fields. ACCEPT_ARTIFACTS is generic dispatch, never generic permission: every fact's own producer/schema/ref/FSM predicates apply at the durable boundary. TRANSITION cannot supply unrelated new canonical facts and requires complete prior transition basis. INGEST_EXTERNAL_LANE_RESULT requires the mechanically authorized external ingestion boundary in addition to all admission predicates; selecting the string proves no trust. Exact retries reuse the original receipt. Changing payload/ID conflicts without mutation.

EventBody is a finite closed union. Data §16's named artifact acceptance events have exactly `{event_type,artifact_ref}`, with the exact target kind from the explicit event table. ArtifactAccepted admits any active fact kind only under its own complete contract; command/commit/receipt/installation trust roots cannot be laundered through it. GateEvaluated has exactly `{event_type,target_ref,result_ref}`; target and decision/assessment result must match the independently validated gate context. No event name is a canonical kind alias.

InstallationRootPinned is an additional closed event `{event_type:"InstallationRootPinned",artifact_ref}` available only in the first initialization commit for the independently qualified exact installation-root facts. It records admission of already externally authorized bytes; it does not create their authority. Every target must equal its external qualified installation pin before validation of the command, including exact schema, policy, spec and trust context. A same-commit root extension or different bytes reject. This event closes bootstrap accounting without allowing generic artifact dispatch to install arbitrary trust roots.

AttemptStarted is a dedicated closed event `{event_type:"AttemptStarted",attempt_ref,assignment_ref,package_binding_ref}`. All three refs are prior accepted before the command, exact assignment/attempt/source/spec compatible, and binding is unique and raw-durable. It derives exactly CREATED→STARTED under the current parent and all existing grants/isolation/source guards. No other event can start an Attempt or imply delivery.

StateTransitionAccepted is a new explicitly registered **event envelope**, not a canonical object kind: `{event_type:"StateTransitionAccepted",aggregate_kind,aggregate_ref,from_state,to_state,basis_refs}`. Aggregate kind is CAMPAIGN|STAGE_RUN|LANE_RUN|ATTEMPT; exact typed aggregate ref is prior accepted and state is independently replayed from history. The state pair must belong to the complete unchanged normative §14 table. basis_refs is the exact prior fact set required by the selected transition predicate; extra/missing/cross-context basis rejects. This envelope cannot represent Attempt CREATED→STARTED, NF02 admission/result acceptance effects, Lane/Stage COMPLETION_ACCEPTED, Campaign GENESIS_ACCEPTED or CAMPAIGN_CONCLUDED. Those effects require the respective dedicated artifact/event contract and full predicates. CANCELLED/CLOSED/blocked/ready/running transitions retain all original purpose-specific guards; syntactic edge legality alone is insufficient. No fallback transition or invented state is added.

The event sequence is generated deterministically: artifact events in canonical object topological order, followed by requested independently legal transitions in payload order. The stored payload events and CommitBody.ordered_event_bodies must equal this derivation. Each artifact has exactly one corresponding acceptance event; no duplicated transition effect. Creation/default state and accepted artifact effects derive only from exact pinned transition semantics. Event bodies contain no accepting commit hash, own ordinal, own head or future receipt. Effective event identity remains the external `(accepting_commit_hash,ordinal)` tuple. Command payload may describe same-commit fact refs, but an event cannot use them to bootstrap a prior-only authority.

IsolationQualification/ContaminationAssessment successor scope is a nonempty ScopeSet of exact source-bound surface/key/invariant/coverage/scope-state subjects. Attempt/channel coverage derives additionally from their prior exact Attempt/Executor/Delivery/channel inventory fields. A broad or empty caller dictionary cannot stand for all channels. Missing material channel proof stays UNKNOWN/DECLARED; CLEAN/ENFORCED still require the original complete independent witness predicates.

Required vectors: unknown command/event; extra payload instruction; serialized trusted/token flag; wrong artifact event target; payload/commit event mismatch; duplicate event/effect; future command/receipt ref; generic transition START/completion/finalization bypass; stale aggregate parent; wrong prior basis; same-commit binding/start; direct ingestion dispatch without trusted boundary. Every negative canonical operation is REJECT plus no canonical mutation.
